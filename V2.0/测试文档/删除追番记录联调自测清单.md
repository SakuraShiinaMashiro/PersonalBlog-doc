# 删除追番记录联调自测清单

## 1. 测试范围

- 进度管理弹窗中的删除入口位置与样式
- 删除前二次确认流程（可复用 `AppConfirmDialog`）
- 删除接口联调（`DELETE /api/anime/{animeId}`）
- 删除成功后列表即时更新与状态计数同步
- 删除失败与防重复提交

## 2. 环境准备

- 后端启动：`PersonalBlog-backend`（默认 `http://localhost:8080`）
- 前端启动：`PersonalBlog-frontend`（默认 `http://localhost:5173`）
- 准备至少 2 条追番记录，便于观察删除后的列表变化

### 3.1 删除按钮位置与样式

- 步骤
  - 打开任意番剧的进度管理弹窗
- 预期
  - 在“看到第N集”按钮右侧看到 `删除追番` 按钮
  - 按钮为红色危险样式，风格与页面按钮体系一致

### 3.2 二次确认弹窗展示

- 步骤
  - 点击 `删除追番`
- 预期
  - 弹出确认框（`AppConfirmDialog`）
  - 标题：`确认删除该追番记录？`
  - 内容：`删除后将清空该番剧的追番进度与开始追番时间，此操作不可恢复。`
  - 按钮：`确认`、`取消`

### 3.3 取消删除

- 步骤
  - 点击确认框 `取消` 或遮罩关闭
- 预期
  - 关闭确认框
  - 列表与进度弹窗数据保持不变

### 3.4 删除成功链路

- 步骤
  - 在确认框点击 `确认`
- 预期
  - 发起 `DELETE /api/anime/{animeId}` 请求
  - 提示 `删除成功`
  - 进度弹窗关闭
  - 列表中该条记录即时移除（无需刷新）
  - 状态 Tabs 数量同步更新

### 3.5 删除失败处理

- 步骤
  - 模拟接口失败（如后端停掉或返回错误）
  - 点击确认删除
- 预期
  - 提示 `删除失败，请重试`
  - 记录不从列表移除
  - 进度弹窗保持当前状态

### 3.6 防重复提交

- 步骤
  - 点击确认删除后快速连续点击
- 预期
  - 确认按钮进入 loading/禁用
  - 仅发起一次删除请求

### 3.7 重新导入验证

- 前置
  - 已成功删除某番剧
- 步骤
  - 使用同一 `bgmId` 重新导入
- 预期
  - 可正常导入为新记录（`CREATED`）

## 4. 接口核对

- 路径：`DELETE /api/anime/{animeId}`
- 成功：

```json
{
  "code": 200,
  "message": "success",
  "data": null
}
```

- 不存在记录示例：

```json
{
  "code": 500,
  "message": "番剧不存在",
  "data": null
}
```

## 5. 回归检查点

- 导入、追番进度快捷操作、修改追番时间功能不受影响
- 多维筛选、状态 Tabs、空态文案行为不退化
- 卡片“开始追番/最近观看”展示正常
