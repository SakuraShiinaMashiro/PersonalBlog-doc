# 追番状态切换功能与追番时间字段完善 详细设计

## 1. 背景与范围

本设计对应 `V2.0` 开发计划中的“追番状态切换功能”任务。

当前项目尚未上线，处于本地开发阶段，因此采用**重建表结构**方案：

- 不做长期新旧模型并行兼容。
- 不做历史数据回填，允许直接删除旧表并重建。
- 直接收敛到 V2.0 最终字段与状态语义。

本设计仅包含三态状态模型：`想看`、`在看`、`已看完`。

---

## 2. 设计目标

1. 完成数据库结构升级：重建 `blog_anime_subject` 与 `blog_anime_progress`，形成 V2.0 最终结构。
2. 完成字段语义收敛：`status`、`track_date`、`last_watch_at` 统一归属进度表。
3. 完成首播时间语义统一：以 `air_date` 为首播日期，`air_year`、`air_season` 作为其派生信息。
4. 完成代码层同步：后端 Entity/DTO/查询与写入逻辑与新结构一致，为后续功能提供稳定基线。

### 2.1 影响范围

- 数据库：`blog_anime_subject`、`blog_anime_progress` 两张表结构与索引定义。
- 后端：`AnimeSubject`、`AnimeProgress` 实体字段，追番列表查询与进度写入逻辑，状态写入入口调整。
- 前端：追番页面状态展示来源切换为 `progress.status`，筛选/排序字段切换为 `progress.track_date`。
- 文档与脚本：本地开发环境建表脚本、联调与验收口径同步更新。

## 3. 最终数据模型

### 3.1 表结构职责

- `blog_anime_subject`：番剧元数据（条目 ID、标题、封面、首播信息、总集数等）。
- `blog_anime_progress`：追番行为数据（状态、已看进度、开始追番时间、最近观看时间）。

### 3.2 字段定义

`blog_anime_subject`：

- `bgm_id`：Bangumi 条目 ID，唯一。
- `title`：番剧标题。
- `image_url`：封面图地址。
- `eps`：总集数。
- `air_date`：首播日期（`DATE`）。
- `air_year`：首播日期对应年份（由 `air_date` 派生）。
- `air_season`：首播日期所在季度（由 `air_date` 派生）。

`blog_anime_progress`：

- `anime_id`：关联 `blog_anime_subject.id`（主键）。
- `status`：追番状态（0: 想看，1: 在看，2: 已看完）。
- `watched_eps`：已看集数 JSON 数组。
- `track_date`：开始追番时间（`DATE`）。
- `last_watch_at`：最近观看时间（`DATETIME`，可空）。

### 3.3 首播季度语义（强约束）

- `1 = 冬`（1-3 月）
- `2 = 春`（4-6 月）
- `3 = 夏`（7-9 月）
- `4 = 秋`（10-12 月）

说明：`air_year`、`air_season` 均表示**首播时间**语义，不是导入时间或用户手动标签。

### 3.4 约束与索引

- `blog_anime_subject.bgm_id`：唯一索引，作为导入幂等与去重底层约束。
- `blog_anime_progress.anime_id`：主键 + 外键，保证一部番剧仅有一条进度记录。
- `blog_anime_progress.status`：仅允许 `0/1/2`（可用 CHECK 约束）。
- 建议索引：
  - `blog_anime_subject.idx_air_date(air_year, air_season)`
  - `blog_anime_progress.idx_status_track_date(status, track_date)`

## 4. 后端改造设计

### 4.1 模型与接口

- `AnimeSubject` 保留元数据字段，补充 `airDate`。
- `AnimeProgress` 增加 `status`、`trackDate`、`lastWatchAt` 字段。
- 列表出参可维持 `subject + progress` 结构，但状态读取来源改为 `progress.status`。
- 入参不允许前端任意修改状态。

### 4.2 状态机规则（三态）

状态由进度自动推导，规则如下：

- `watchedEpisodes == 0` -> `想看`
- `0 < watchedEpisodes < totalEpisodes` -> `在看`
- `watchedEpisodes >= totalEpisodes` -> `已看完`

实现说明（JSON 数组场景）：
- `watchedEpisodes` 来源于 `watched_eps` JSON 数组中去重且在有效范围 `[1, eps]` 内的元素数量。
- 应用层读取 `watched_eps -> List<Integer>` 后以去重后的 `size` 计算。
- 由后端统一实现状态推导逻辑，不再提供独立手动改状态入口。

### 4.3 进度写入联动

- 所有进度写操作在落库时同步更新：
  - `status`（按状态机规则重新计算）
  - `last_watch_at`（置为当前时间）
- `track_date` 在初始化进度记录时写入（通常为导入/加入追番时间）。
- `last_watch_at` 仅后端维护，前端只读展示。

### 4.4 SQL（MySQL 8.0，本地开发重建方案）

```sql
-- 本脚本用于本地开发环境：允许直接删表重建，不做历史数据回填。

SET FOREIGN_KEY_CHECKS = 0;

DROP TABLE IF EXISTS `blog_anime_progress`;
DROP TABLE IF EXISTS `blog_anime_subject`;

SET FOREIGN_KEY_CHECKS = 1;

CREATE TABLE `blog_anime_subject` (
    `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `bgm_id` INT NOT NULL COMMENT 'Bangumi条目ID',
    `title` VARCHAR(255) NOT NULL COMMENT '番剧标题',
    `image_url` VARCHAR(500) NULL COMMENT '封面图URL',
    `eps` INT DEFAULT 0 COMMENT '总集数',
    `air_date` DATE NULL COMMENT '首播日期',
    `air_year` INT NULL COMMENT '首播年份（由air_date派生）',
    `air_season` TINYINT NULL COMMENT '首播季度（1冬,2春,3夏,4秋）',
    `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_bgm_id` (`bgm_id`),
    KEY `idx_air_date` (`air_year`, `air_season`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='番剧元数据表';

CREATE TABLE `blog_anime_progress` (
    `anime_id` BIGINT NOT NULL COMMENT '关联 blog_anime_subject.id',
    `status` TINYINT NOT NULL DEFAULT 0 COMMENT '追番状态 (0:想看, 1:在看, 2:已看完)',
    `watched_eps` JSON NULL COMMENT '已看集数列表(JSON数组)',
    `track_date` DATE NOT NULL COMMENT '开始追番时间',
    `last_watch_at` DATETIME NULL COMMENT '最近观看时间',
    `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`anime_id`),
    KEY `idx_status_track_date` (`status`, `track_date`),
    CONSTRAINT `fk_progress_subject` FOREIGN KEY (`anime_id`) REFERENCES `blog_anime_subject` (`id`) ON DELETE CASCADE,
    CONSTRAINT `chk_progress_status` CHECK (`status` IN (0, 1, 2))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='追番进度表';

-- 可选验证 SQL
SELECT `status`, COUNT(*) AS cnt
FROM `blog_anime_progress`
GROUP BY `status`;

SELECT `bgm_id`, COUNT(*) AS dup_cnt
FROM `blog_anime_subject`
GROUP BY `bgm_id`
HAVING COUNT(*) > 1;
```

## 5. 前端适配要求

- 状态展示改为只读，读取 `progress.status`，不再提供手动状态选择。
- 通过进度相关操作驱动状态变化。
- 筛选排序能力对接新字段：`progress.status` 与 `progress.track_date`。

## 7. 验收标准

### 7.1 数据层

- `blog_anime_subject`、`blog_anime_progress` 按新结构创建成功。
- `blog_anime_subject.bgm_id` 唯一索引生效。
- `blog_anime_progress.status` 仅出现 `0/1/2`。
- `air_year`、`air_season` 语义符合 `air_date` 派生规则。

### 7.2 行为层

- 进度变化可正确触发状态自动切换（写入 `progress.status`）。
- 进度写操作可正确更新 `progress.last_watch_at`。
- 导入/新增番剧可正确初始化 `progress.track_date`。

### 7.3 联调层

- 前端状态只读展示正常（来源 `progress.status`）。
- 列表筛选/排序可基于状态与 `track_date` 正常工作。
- 首播时间展示与筛选语义一致（`air_date`/`air_year`/`air_season`）。

## 8. 风险与处理

- 风险：误在非本地环境执行删表脚本导致数据丢失。
  - 处理：脚本与文档明确“仅限本地开发环境”，执行前二次确认环境。
- 风险：季度映射语义使用不一致。
  - 处理：统一采用 `1冬(1-3) / 2春(4-6) / 3夏(7-9) / 4秋(10-12)` 并在代码中集中转换。
- 风险：状态来源切换后前后端字段引用遗漏。
  - 处理：联调阶段重点核查 `subject.status` 到 `progress.status` 的替换完整性。
