# 搜索场景语义化异常反馈 详细设计

## 1. 背景与范围

本设计对应 `V2.0` 开发计划中的“搜索场景语义化异常反馈”需求，目标是将追番搜索场景中的两类结果进行明确区分：

- 搜索成功但无结果；
- 搜索请求失败（外部服务异常、超时、网络错误等）。

当前实现中，后端搜索异常会兜底返回空列表，前端无法感知失败语义，导致“失败”被误展示为“无结果”。

本次改造仅覆盖追番页面“搜索新番”弹窗内搜索流程，不涉及导入逻辑、列表筛选逻辑和进度管理逻辑。

---

## 2. 设计目标

1. 后端返回语义正确：异常不再伪装为空结果。
2. 前端状态可区分：`idle/loading/success/empty/error`。
3. 用户反馈清晰：无结果与失败展示不同 UI 与文案。
4. 错误码统一管理：采用枚举类集中维护，避免魔法数字散落。

---

## 3. 语义定义

### 3.1 搜索结果语义

- `成功有结果`：接口返回 `code = 200` 且 `data.size > 0`。
- `成功无结果`：接口返回 `code = 200` 且 `data.size = 0`。
- `搜索失败`：接口返回 `code != 200` 或前端发生网络层异常。

### 3.2 前端状态机

- `idle`：默认态，尚未执行搜索。
- `loading`：请求进行中。
- `success`：搜索成功且有结果。
- `empty`：搜索成功但无结果。
- `error`：搜索失败。

状态流转：`idle -> loading -> success|empty|error`。

---

## 4. 错误码设计

### 4.1 错误码约定

- `40001`：关键词为空或仅空格。
- `50301`：Bangumi 搜索服务不可用/请求失败。
- `50302`：Bangumi 搜索超时。

### 4.2 错误码承载方式

使用枚举类统一管理错误码与默认文案。

- 推荐类名：`BizErrorCode`
- 推荐包路径：`com.czf.blog.exception.code`

说明：该位置与现有 `BizException`、`GlobalExceptionHandler` 异常链路一致，便于统一维护与跨模块复用。

---

## 5. 接口设计

### 5.1 接口保持不变

- Method: `GET`
- Path: `/api/anime/search`
- Query: `keyword`

### 5.2 响应语义

成功（有结果或无结果）：

```json
{
  "code": 200,
  "message": "success",
  "data": []
}
```

失败（示例）：

```json
{
  "code": 50301,
  "message": "搜索服务暂时不可用，请稍后重试",
  "data": null
}
```

---

## 6. 后端改造设计

### 6.1 涉及文件

- `PersonalBlog-backend/src/main/java/com/czf/blog/service/impl/AnimeServiceImpl.java`
- `PersonalBlog-backend/src/main/java/com/czf/blog/exception/BizException.java`
- `PersonalBlog-backend/src/main/java/com/czf/blog/handler/GlobalExceptionHandler.java`（逻辑基本沿用）
- `PersonalBlog-backend/src/main/java/com/czf/blog/exception/code/BizErrorCode.java`（新增）

### 6.2 `searchBangumi` 行为调整

1. 关键词判空：`keyword == null || keyword.trim().isEmpty()` 时抛 `BizException(BizErrorCode.KEYWORD_EMPTY)`。
2. 调用 Bangumi 成功：返回真实结果（允许空列表）。
3. 调用超时：抛 `BizException(BizErrorCode.BANGUMI_SEARCH_TIMEOUT)`。
4. 其他调用异常：抛 `BizException(BizErrorCode.BANGUMI_SEARCH_UNAVAILABLE)`。

### 6.3 异常处理约定

- `GlobalExceptionHandler` 继续将 `BizException` 转换为 `Result.error(code, message)`。
- 不在 `catch` 中返回空列表，不吞异常语义。

---

## 7. 前端改造设计

### 7.1 涉及文件

- `PersonalBlog-frontend/src/views/AnimeView.vue`
- `PersonalBlog-frontend/src/api/anime.ts`（接口签名保持不变）

### 7.2 状态字段

在搜索弹窗逻辑中增加：

- `searchState: 'idle' | 'loading' | 'success' | 'empty' | 'error'`
- `searchErrorMessage: string`
- `lastSearchedKeyword: string`

沿用：`keyword`、`searchResults`。

### 7.3 搜索流程

1. 点击搜索或回车：先 `trim` 关键词。
2. 关键词为空：提示“请输入搜索关键词”，不发请求。
3. 请求开始：`searchState = loading`，清空错误信息。
4. 请求成功：
   - `searchResults.length > 0` -> `success`
   - `searchResults.length === 0` -> `empty`
5. 请求失败：`searchState = error`，展示后端错误 message（无 message 时使用兜底文案）。

### 7.4 搜索区 UI 语义

- `idle`：展示引导文案“搜索你想追的番剧”。
- `loading`：展示“正在搜索中...”。
- `success`：展示结果列表。
- `empty`：展示“未找到与‘关键词’相关的番剧”。
- `error`：展示失败提示 + “重试”按钮。

### 7.5 交互约束

- 加载中禁用搜索按钮，避免重复并发提交。
- “重试”默认复用最近一次关键词。
- 关闭搜索弹窗时重置状态为 `idle`（推荐）。

---

## 8. 验收标准

### 8.1 功能验收

- 关键词命中：显示结果列表。
- 关键词未命中：显示“无结果”态，不显示错误态。
- 模拟外部服务失败：显示“错误”态，并可重试。
- 模拟超时：返回 `50302`，前端展示超时提示。
- 关键词为空：不发请求，提示输入关键词。

### 8.2 语义验收

- 后端异常不再返回空数组伪装成功。
- 前端不再通过“空数组”推断失败。
- 前后端对 `code/message` 语义解释一致。

---

## 9. 风险与处理

- 风险：外部搜索服务波动导致错误态频繁出现。
  - 处理：前端提供重试入口，后端保留完整异常日志。
- 风险：用户快速连续输入并搜索，旧请求覆盖新请求。
  - 处理：可选增加请求序号，仅采纳最后一次响应。
- 风险：错误文案不统一。
  - 处理：统一由 `BizErrorCode` 提供默认 message。

---

## 10. 结论

本方案通过“错误码枚举统一管理 + 后端异常语义还原 + 前端状态机展示”三层改造，实现“无结果”与“请求失败”的清晰区分。该方案改造范围可控、兼容现有接口结构，能够显著提升追番搜索体验与问题定位效率。
