# 多维度筛选已追番剧 详细设计

## 1. 背景与范围

本设计对应 `V2.0` 开发计划中的“多维筛选与复合排序”需求，目标是明确“已追番剧列表”在真实使用场景下的筛选与排序行为。

结合当前页面与需求讨论，确认以下问题：

- 不再默认按“放映年份 + 放映季度”限制首屏结果；
- 首屏应展示用户全部追番记录；
- 默认排序应体现“最近在追什么”，即按最近观看时间排序；
- 放映维度应作为用户主动筛选条件；
- 需要支持按开始追番时间段筛选。

本次设计仅覆盖“追番管理页列表查询/筛选/排序”行为，不涉及导入、快捷进度操作等其他功能改造。

---

## 2. 设计目标

1. 首屏默认展示全量追番记录，减少用户进入页面后的空白或误筛选感知。
2. 默认按 `progress.lastWatchAt` 从近到远排序，体现最近活跃记录优先。
3. 保持“状态筛选 Tabs”现有前端样式不变，仅调整其他筛选逻辑。
4. 支持放映维度筛选：`放映年份` + `放映季度`。
5. 支持开始追番时间段筛选：`trackDateStart ~ trackDateEnd`（闭区间）。
6. 放映年份/季度选项仅展示实际存在数据，避免无效选项。

---

## 3. 功能定义（最终口径）

### 3.1 默认展示与排序

- 用户进入追番管理页时，请求全量追番记录（不带放映年份/季度筛选）。
- 列表默认按 `progress.lastWatchAt DESC` 排序。
- `lastWatchAt = null` 的记录排在最后。
- 排序兜底：`trackDate DESC`（保证顺序稳定）。

### 3.2 筛选维度

- 状态筛选：`全部 / 想看 / 在看 / 已看完`（样式保持现状）。
- 放映年份筛选：可选，默认“全部年份”。
- 放映季度筛选：可选，默认“全部季度”。
- 开始追番时间段筛选：`trackDateStart`、`trackDateEnd`。

### 3.3 复合筛选规则

- 各条件之间为 AND 关系（交集）。
- 时间段判断为闭区间：`trackDateStart <= trackDate <= trackDateEnd`。

### 3.4 放映年份/季度选项约束

- 放映年份下拉仅展示“追番清单中实际存在的 `airYear`”。
- 未出现在清单中的年份不展示。
- 放映季度下拉仅在“已选择放映年份”后显示或启用。
- 选择某放映年份后，季度选项仅展示该年份下实际存在的季度（1~4 的子集）。
- 当用户切换放映年份时，若当前已选季度不在新年份可选集合中，则自动清空季度为“全部季度”。

---

## 4. 交互设计

### 4.1 页面初始行为

1. 打开页面后立即加载全量列表。
2. 状态 Tab 默认“全部”。
3. 放映年份默认“全部年份”；放映季度默认“全部季度（禁用或隐藏）”。
4. 时间段默认未设置。

### 4.2 筛选区布局要求

- 保持现有状态 Tabs 区域样式不变。
- 在顶部筛选区增加或调整为：
  - 开始追番时间范围（开始日期、结束日期）；
  - 放映年份下拉；
  - 放映季度下拉（依赖年份）；
  - 重置筛选按钮。

### 4.3 空状态文案

- 统一文案为：`当前筛选条件下暂无追番记录`。
- 不再使用“这个季度还没有番剧”这类强绑定季度的文案。

## 5. 后端设计

### 5.1 接口沿用

- 沿用现有接口：`GET /api/anime/list`。
- 现阶段无需新增接口路径。
- 请求方式为 Query 参数，不使用 Request Body。

### 5.2 查询参数定义（Query）

`GET /api/anime/list` 支持以下可选参数：

- `status`：追番状态（`0/1/2`）；
- `year`：放映年份（沿用现有命名）；
- `season`：放映季度（`1-4`，沿用现有命名）；
- `trackDateStart`：开始追番起始日期（后端类型 `LocalDate`）；
- `trackDateEnd`：开始追番结束日期（后端类型 `LocalDate`）。

说明：`trackDateStart/trackDateEnd` 的输入格式由前端日期组件保证，后端不做重复的格式校验逻辑，仅做业务规则校验。

补充说明：当前前端“状态 Tabs（全部/想看/在看/已看完）”采用本地过滤实现，不向后端传 `status`；后端保留 `status` 作为可选兼容参数，供后续扩展或其他调用方使用。

### 5.3 查询与排序规则

`AnimeService#getAnimeListWithProgress` 调整为：

- 当未传筛选参数时，返回全量数据；
- 各筛选条件之间为 AND 关系；
- 当传入时间段时，按闭区间过滤：`trackDateStart <= trackDate <= trackDateEnd`；
- 默认排序改为：
  1. `progress.lastWatchAt DESC`（nulls last）
  2. `progress.trackDate DESC`（兜底）
  3. `subject.id DESC`（稳定排序兜底）

说明：即使前端具备本地筛选能力，后端仍应提供一致的默认顺序，保证跨端一致性。

### 5.4 参数兼容与校验策略

- 保留既有参数能力（如放映年份/季度过滤）以兼容旧调用；
- 若前端采用全量拉取 + 本地复合筛选，可不传这些筛选参数。
- 其中 `status` 当前由前端本地过滤处理，前端现阶段不传。
- 后端仅做业务约束校验：
  - `status` 仅允许 `0/1/2`；
  - `season` 仅允许 `1-4`；
  - `trackDateStart > trackDateEnd` 时返回参数错误。

### 5.5 接口请求与响应示例

请求示例（全量默认排序）：

```http
GET /api/anime/list
```

请求示例（复合筛选）：


## 6. 前端设计

### 6.1 数据模型

在 `AnimeView` 中维护：

- `animeList`：全量追番列表（后端返回）；
- `activeTab`：状态筛选值（沿用，纯前端本地过滤）；
- `selectedAirYear`：放映年份（可空）；
- `selectedAirSeason`：放映季度（可空）；
- `trackDateStart`、`trackDateEnd`：开始追番时间段（可空）。

补充说明：状态 Tabs 不触发后端请求参数变化；当前前端的放映年份/季度与追番时间段筛选也在本地完成，因此当前前端调用 `/api/anime/list` 时不携带筛选参数。

### 6.2 选项生成规则

- `availableAirYears`：从 `animeList` 中提取非空 `subject.airYear`，去重后降序。
- `availableAirSeasons`：基于当前 `selectedAirYear` 对应子集提取 `subject.airSeason`，去重后升序。

### 6.3 列表计算逻辑

`filteredList` 计算顺序建议：

1. 基于状态过滤（`activeTab`）；
2. 基于放映年份过滤；
3. 基于放映季度过滤；
4. 基于 `trackDate` 时间段过滤（闭区间）；
5. 最终按 `lastWatchAt DESC`（nulls last）+ `trackDate DESC` 排序。

请求与过滤实现细节：

- 当前前端进入页面时请求一次全量数据：`GET /api/anime/list`；
- `activeTab`、`selectedAirYear`、`selectedAirSeason`、`trackDateStart`、`trackDateEnd` 均在前端 `computed filteredList` 内本地过滤；
- 当前前端不向后端传 `status/year/season/trackDateStart/trackDateEnd`。

### 6.4 联动规则

- `selectedAirYear` 改变时，重新计算季度选项；
- 若当前 `selectedAirSeason` 无效，自动清空。

### 6.5 样式约束

- 状态筛选 Tabs 样式、配色、交互保持现状，不做视觉改版。
- 其他筛选条件的样式必须符合网站的整体风格

## 7. 边界与异常处理

1. `airYear` 为空的数据：
   - 在“全部年份”下可见；
   - 选中具体年份时自动排除。
2. `trackDate` 为空的数据：
   - 时间段未设置时可见；
   - 时间段筛选启用时默认排除。
3. 仅设置开始日期或仅设置结束日期：
   - 仅开始：`trackDate >= start`；
   - 仅结束：`trackDate <= end`。
4. `start > end`：
   - 前端禁止提交或自动交换；
   - 推荐提示：`开始日期不能晚于结束日期`。

## 8. 验收标准

### 8.1 功能验收

- 首屏展示全量记录，不受放映年份/季度默认值影响。
- 默认按 `lastWatchAt` 从近到远；`lastWatchAt` 为空在后。
- 状态 Tabs 样式与当前版本一致。
- 放映年份下拉只出现真实存在年份。
- 选择放映年份后，放映季度只出现该年份真实存在季度。
- 切换放映年份导致季度失效时，季度自动重置为“全部季度”。
- 时间段筛选按闭区间生效。
- 多条件同时生效时结果为交集。

### 8.2 文案验收

- 空状态文案为：`当前筛选条件下暂无追番记录`。

---

## 9. 风险与处理

- 风险：前端本地筛选条件较多，后续维护容易出现条件遗漏。
  - 处理：集中在单一 `computed filteredList` 中统一维护，并增加注释说明过滤顺序。
- 风险：日期字符串与时区转换导致边界偏差。
  - 处理：前后端统一使用 `yyyy-MM-dd` 处理 `trackDate`，前端比较时按本地日期零点归一。
- 风险：`lastWatchAt` 空值较多导致“最近活跃”辨识度不足。
  - 处理：保留 `trackDate` 兜底排序，避免展示顺序随机。

---

## 10. 结论

本方案将追番页从“按季度入口”调整为“全量记录 + 主动筛选”的使用模式，默认聚焦最近观看行为，同时保留放映维度与追番时间段的精细过滤能力。在不改动状态 Tabs 样式的前提下，提升了首屏可用性与筛选效率，满足 V2.0 对多维筛选与复合排序的目标。



* 目前的实现，由于进入页面拉去了全量的追番数据，所以后面过滤操作不再请求接口，全在前端完成过滤。接口的参数作为后期扩展使用
