# 删除追番记录 详细设计

## 1. 背景与范围

本设计对应 `V2.0` 开发计划中的“删除追番记录”需求，目标是让用户可以在追番管理中删除不再需要的番剧记录。

本次设计覆盖：

- 单条追番记录删除；
- 前端删除入口、确认交互、结果反馈；
- 后端删除接口与异常处理。

本次不覆盖：

- 批量删除；
- 回收站/恢复；
- 删除审计与历史追踪。

---

## 2. 现有情况（基线）

数据库已具备以下结构特性：

- `blog_anime_subject` 为番剧主表；
- `blog_anime_progress` 为进度表；
- 外键 `fk_progress_subject` 配置了 `ON DELETE CASCADE`。

结论：删除 `blog_anime_subject` 主记录后，关联 `blog_anime_progress` 会自动级联删除，无需额外清理逻辑。

---

## 3. 方案口径（最终）

### 3.1 删除策略

- 采用**物理删除**。
- 不采用逻辑删除（当前版本无回收站和审计需求，保持实现简单）。

### 3.2 删除对象

- 按本地 `animeId` 删除一条追番记录（主表 + 级联进度）。

### 3.3 删除后行为

- 列表中即时移除该记录；
- 后续可重新导入同一 `bgmId`，按首次导入流程重新创建。

---

## 4. 前端交互设计

### 4.1 入口位置

- 入口放在“进度管理弹窗”中。
- 位于“看到第N集”按钮右侧（同一行）。

### 4.2 按钮设计

- 文案：`删除追番`
- 样式：符合网站风格的红色危险按钮（与现有按钮圆角、阴影、动效一致）。

### 4.3 二次确认

- 点击删除按钮后弹出确认。
- 前端需封装一个可复用的确认框组件（建议命名：`AppConfirmDialog`），本功能直接复用该组件，不在页面内写一次性确认弹层。
- 建议文案：
  - 标题：`确认删除该追番记录？`
  - 内容：`删除后将清空该番剧的追番进度与开始追番时间，此操作不可恢复。`
  - 按钮：`确认` / `取消`

### 4.4 提示与状态

- 成功提示：`删除成功`
- 失败提示：`删除失败，请重试`
- 删除请求期间按钮进入 loading/禁用，避免重复提交。

---

## 5. 后端设计

### 5.1 接口设计

- Method: `DELETE`
- Path: `/api/anime/{animeId}`

请求示例：

```http
DELETE /api/anime/1001
```

成功响应示例：

```json
{
  "code": 200,
  "message": "success",
  "data": null
}
```

失败响应示例：

```json
{
  "code": 500,
  "message": "番剧不存在",
  "data": null
}
```

### 5.2 服务实现

- `AnimeService` 新增：`void deleteAnime(Long animeId)`
- `AnimeServiceImpl`：
  1. 校验 `animeId` 对应记录存在；
  2. 执行 `subjectMapper.deleteById(animeId)`；
  3. 依赖外键级联删除进度数据。

### 5.3 异常策略

- `animeId` 不存在：抛出 `BizException("番剧不存在")`。

---

## 6. 前端实现设计

- `animeApi` 新增删除方法：`deleteAnime(animeId)`。
- 新增可复用确认框组件：`AppConfirmDialog`。
  - 设计目标：统一全站危险操作确认交互（删除、清空、重置等）。
  - 建议 Props：
    - `modelValue: boolean`（控制显示/隐藏）
    - `title: string`
    - `message: string`
    - `confirmText?: string`（默认 `确认`）
    - `cancelText?: string`（默认 `取消`）
    - `danger?: boolean`（危险态样式）
    - `loading?: boolean`（确认按钮加载态）
  - 建议 Emits：`update:modelValue`、`confirm`、`cancel`
  - 样式要求：与现有 `AppNoticeDialog` 风格一致，危险态按钮使用红色主题。
- `AnimeView` 在进度弹窗添加删除按钮，并通过 `AppConfirmDialog` 承载确认逻辑。
- 删除成功后：
  - 关闭进度弹窗；
  - 更新列表（本地移除或重新拉取）；
  - 状态计数随列表同步更新。

---

## 7. 验收标准

1. 用户可在进度弹窗中通过红色“删除追番”按钮删除记录。
2. 删除前必须二次确认。
3. 删除成功后列表即时更新，不需手动刷新。
4. 删除后重新导入同一番剧可正常创建新记录。
5. 删除失败时有明确错误提示，不影响其他记录。

---

## 8. 风险与处理

- 风险：误删。
  - 处理：二次确认 + 危险色按钮 + 清晰提示文案。
- 风险：重复点击导致重复请求。
  - 处理：删除按钮 loading 与禁用。

---

## 9. 结论

本方案采用物理删除，并基于现有外键级联能力实现“主记录与进度同步删除”。在前端通过明确的危险操作入口和二次确认机制降低误删风险，在不增加复杂数据治理成本的前提下满足 V2.0 删除追番记录需求。
