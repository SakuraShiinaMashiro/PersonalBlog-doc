# PersonalBlog V2.0 需求分析文档（追番模块）

## 1. 背景与目标

### 1.1 背景
当前 V1.0 已完成追番模块的基础能力：
- 支持 Bangumi 番剧搜索与导入；
- 支持按季度查看番剧列表；
- 支持单集勾选与状态切换（想看/在看/已完结）。

在实际使用中，仍存在以下问题：
- 重复导入时用户反馈不明确，易产生困惑；
- 搜索失败与无结果场景区分不清；
- 列表筛选与排序维度较少，不利于回顾；
- 进度操作偏基础，缺少高频快捷动作。

### 1.2 目标
V2.0 聚焦追番模块深化，目标为：
- 将“可用”提升为“稳定、清晰、可持续使用”；
- 完成按追番时间查看能力；
- 优化搜索、导入、筛选、进度管理的整体体验。

---

## 2. 范围定义

### 2.1 In Scope（本期范围）
- 追番搜索与导入体验优化；
- 追番列表筛选与排序增强；
- 进度管理增强（含快捷操作）；
- 状态管理与进度联动规则完善；
- 错误处理与提示优化（含外部 API 异常场景）。

### 2.2 Out of Scope（本期不做）
- 每日打卡模块；
- 全局统计看板；
- 全站搜索与标签体系重构；
- 多用户权限系统全面改造。

---

## 3. 用户场景与核心流程

### 3.1 核心用户场景
- 场景 A：用户搜索新番并导入到个人追番库。
- 场景 B：用户每天更新看到的集数并快速同步状态。
- 场景 C：用户按季度/状态/最近追更回顾自己的追番记录。

### 3.2 核心流程
1. 用户输入关键词进行搜索；
2. 在结果列表中选择目标番剧并导入；
3. 导入后进入当前季度列表，更新集数进度；
4. 系统自动记录最近追更时间；
5. 用户通过筛选与排序快速回顾追番状态。

---

## 4. 功能需求

### 4.1 搜索与导入
- 支持关键词搜索 Bangumi 番剧；
- 搜索接口需区分“无数据”与“请求失败”；
- 导入需具备幂等行为：重复导入给出明确提示；
- 导入成功后可立即在本地列表中可见。

### 4.2 列表与筛选
- 支持按年份、季度、状态组合筛选；
- 支持按最近追更时间排序；
- 默认展示逻辑清晰，筛选条件可持续保留（同页操作期间）。

### 4.3 进度管理
- 支持单集已看/未看切换；
- 支持快捷操作：看到第 N 集、全部看完、重置进度；
- 集数操作应进行有效性校验（范围合法）；
- 已看集数在展示与存储层保持有序、去重。

### 4.4 状态管理
- 支持状态切换：想看 / 在看 / 已完结；
- 状态与进度应有基本联动规则（如“全部看完”可自动建议设为已完结）。

---

## 5. 非功能需求

### 5.1 性能
- 常规列表查询响应时间目标：< 500ms（本地开发环境除外）；
- 搜索接口超时可配置，避免长时间阻塞。

### 5.2 稳定性
- 外部 API 异常时系统应返回可识别错误，不影响本地已导入数据浏览；
- 导入与进度更新需保证数据一致性。

### 5.3 可用性
- 前端对关键操作提供明确反馈（成功/失败/重复导入）；
- 错误提示面向用户可理解，避免仅输出技术异常。

### 5.4 可维护性
- 后端优先使用明确 VO/DTO，而非松散 Map 结构；
- 保持接口语义一致，便于后续扩展。

---

## 6. 数据与接口影响

### 6.1 数据层影响
- 评估并新增“追更时间”字段（建议在进度表维护 `update_time`）；
- 保持 `blog_anime_subject` 与 `blog_anime_progress` 的主从一致性；
- 对唯一键与状态字段约束进行复核。

### 6.2 接口层影响
- 现有接口增强：
  - `GET /api/anime/search`（错误语义与分页能力）
  - `POST /api/anime/import`（幂等导入）
  - `GET /api/anime/list`（筛选排序参数增强）
  - `POST /api/anime/toggle`（参数校验增强）
  - `PUT /api/anime/status`（状态规则增强）
- 可选新增接口：
  - 快捷进度更新接口（如“看到第 N 集”）；
  - 批量状态更新接口。

### 6.3 兼容性
- 保持现有前端基础调用可继续使用；
- 新增参数采用可选方式，避免破坏 V1 页面逻辑。

---

## 7. 验收标准与里程碑

### 7.1 验收标准（简版）
- 重复导入同一番剧不会产生 500 异常，且提示明确；
- 用户可按“年份 + 季度 + 状态 + 最近追更”进行查询；
- 用户可通过快捷操作在 3 次点击内完成常见进度更新；
- 外部搜索失败时，前端可展示可读错误，不误导为“无结果”。

### 7.2 里程碑建议
- 里程碑 1：数据结构与接口契约调整（幂等、排序字段、校验规则）；
- 里程碑 2：后端核心功能实现与联调；
- 里程碑 3：前端交互优化与回归验证。

### 7.3 风险与依赖
- 依赖 Bangumi API 可用性与网络质量；
- 导入高频场景下可能出现第三方限流；
- 需要预留失败重试与降级提示策略。
