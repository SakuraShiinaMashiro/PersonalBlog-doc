# 概要设计

### 1 历史数据迁移与字段兼容 (Data Migration)

*   **功能说明**：
    *   **数据库变更**：新增 `track_date`（追番日期）和 `last_watch_at`（最近观看时间）字段；为 `bangumi_id` 添加唯一索引。
    *   **历史回填**：编写脚本，将旧状态值（如“已完结”）映射为 V2.0 标准（“已看完”）；根据创建时间回填历史记录的 `track_date`。
    *   **代码同步**：更新后端 Entity 和 DTO 结构，确保与新表结构一致。

### 2 导入幂等性校验与重复提示 (Idempotent Import)

*   **功能说明**：
    *   **幂等处理**：导入时若 `bangumi_id` 已存在，系统执行更新操作而非报错或重复插入，接口返回 `imported: false` 标记。
    *   **用户反馈**：当前端收到“已存在”标记时，弹出提示语“该番剧已在追番列表中，已为您同步最新信息”，增强导入闭环的明确性。

### 3 进度驱动的状态自动联动 (Auto Status Management)

*   **功能说明**：
    *   **状态机逻辑**：实现后端核心规则：已看集数为 0 -> **想看**；已看集数 > 0 且未满 -> **在看**；已看完全部 -> **已看完**。
    *   **接口重构**：屏蔽前端手动修改状态的入口，所有状态切换必须由进度写操作触发。
    *   **前端适配**：状态展示改为只读标签，不再显示下拉选择框。

### 4 追番进度快捷操作 (Quick Progress Actions)

*   **功能说明**：
    *   **操作接口**：实现“看到第 N 集”、“一键看完”、“重置进度”三个原子化 API。
    *   **联动更新**：每次操作进度时，后端自动更新 `last_watch_at` 字段。
    *   **UI 集成**：在番剧列表卡片或详情页新增这些高频操作的快捷按钮。

### 5 追番时间维度与多维筛选排序 (Multi-dim Filter & Sort)

*   **功能说明**：
    *   **多维筛选**：后端实现按“追番年份/季度”、“放映年份/季度”及“观看状态”的组合查询。
    *   **排序增强**：支持按最近追更时间（默认）、开始追番日期、首播日期进行正反序排列。
    *   **筛选面板**：前端开发多功能筛选组件，并确保操作后筛选条件不丢失。

### 6 搜索场景语义化异常反馈 (Search Error Handling)

*   **功能说明**：
    *   **语义区分**：后端精准识别 Bangumi API 的不同返回状态：成功但无数据（200 OK, empty data）vs API 故障/超时（非 200 或异常）。
    *   **前端差异化提示**：针对“无搜索结果”展示空状态图片；针对“网络异常”展示重试按钮，不再混为一谈。
